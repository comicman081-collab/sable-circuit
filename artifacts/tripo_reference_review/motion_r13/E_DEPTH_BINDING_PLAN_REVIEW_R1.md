# Independent review of the E inverse-projection depth proposal

Design verdict: **appropriate bounded rig-support hypothesis; implementation and execution remain unapproved**. The new proposal addresses a real deficiency in treating a foreshortened source boot as a vertical, zero-depth chain. Preserving complete source RGBA/UV while changing invisible deformation support, bone placement and weights stays within the source-preserving motion boundary. It must not become authority to invent a visible body, boot, costume or any unobserved art.

Reviewed plan: `combat_E_r01/DEPTH_BINDING_PLAN_R1.md`, SHA256 `559334eee28f1a72164635e63ae0300ca7ab73e88736fb2665d6e792145ff765`. Read the actual foot-reach/orientation probes, `source_projection_binding.py`, `limb_target_solver.py`, its four tests and the 22-joint depth probe. No test, mesh, render or motion job was executed by this reviewer for this design review.

The current probe's 1.209225 maximum right reach ratio establishes failure of that exact previous target construction, not proof of a uniquely correct replacement camera or anatomy. The proposed depth probe reports zero reprojection error for 22 joints and leg lengths L0.855228/R0.849208 m. Those are useful algebraic results only. A single view leaves depth undetermined. Thirty degrees is a declared fit assumption, not a measured camera recovered from ImageGen art or validated by licensing.

Before any Blender candidate, the numeric contract should fix the following:

1. **Projection and units.** Define the camera's complete basis and origin, source pixel origin, image dimensions, orthographic span and metres-per-pixel. For Blender X-right/Y-depth/Z-up, the stated equation assumes screen up `h = y sin(theta) + z cos(theta)` and view normal `(0,-cos(theta),sin(theta))`. Bind the sign, axis conversion and exact 30-degree value. `mpp_new = mpp_original cos(theta)` changes horizontal physical scale as well as camera span. It cannot be silently applied to a second display or movement scale. Reject nonfinite, malformed, out-of-bounds source constraints and degenerate elevations at the consuming boundary.
2. **Actual fitted dimensions.** Bind the exact licensed reference, height normalization and reference rest transforms. Report every left/right thigh, calf, ankle-to-ball/toe, pelvis width and neutral depth extent—not only mean leg length or maximum depth. Declare acceptable proportions before fitting the gait; do not enlarge support geometry until a failed action happens to reach. The source `ball` pixels are art toe estimates; assigning the reference ball height does not automatically calibrate heel, ankle and sole offsets.
3. **Neutral source surface.** Define both sole outlines from actual visible original rubber pixels and record precise UV/vertex IDs. Derive one static height/depth field shared by all coincident source vertices, including region-split waist/coat roots. Constrain both neutral sole sets to a single floor before evaluating motion. Preserve source UVs, exact RGBA, semantic ownership and the shared torso weight transition; keep the upper gun/grip pixels rigidly on their reviewed upper bone. Unobserved closure remains transparent.
4. **Numeric acceptance.** For all front vertices and all 22 source joints, report maximum and per-region reprojection error; a proposed arithmetic target is at most 1e-4 source pixel, separately from later raster comparison. Report finite coordinates, positive segment lengths, coincident-UV boundary differences, front triangle orientation and surface depth extrema. For the fixed-length solver, independently recompute both lengths and ankle error (proposed numeric tolerance 1e-6 m), verify exact hip preservation and fail unreachable targets. These are proposed implementation tolerances, not replacements for existing production gates.
5. **Actual target feasibility.** Before expensive rendering, evaluate all 49 exact reference timestamps with the proposed target rest geometry. Record per-side target distance versus `[abs(thigh-calf), thigh+calf]`, positive reach margin where available, actual knee bend-plane continuity and endpoint closure. Do not silently clamp, stretch, switch knee side or shift root. Use actual target shoe offsets and stance geometry, not a copied reference clearance as a self-validating sole measurement. A new leg ratio changes derived travel distance; independently specified actor speed and measured world displacement remain required later.
6. **Runtime projection parity.** Current `SourceSkinViewport` uses a horizontal authored-view camera. A Blender-only 30-degree change would break appearance on export. The exact authored projection and metre convention must be bound into the new skin input and consumed consistently by Blender capture, Godot camera, skeleton axes, barrel/grip projection, recoil and actor-to-display mapping. Preserve a single explicit movement/display unit relationship. A passing source-pixel round trip does not prove this caller integration.

The existing two-link solver is suitably small and rejects unreachable targets or a degenerate knee plane without root translation or leg stretching. Its isolated four test cases do not show that this new 49-sample target set is reachable or that skin-weighted soles follow the ankle.

After the numeric constraints and implementation are independently reviewed, the planned order remains sensible: one exact neutral probe with native source-preservation, topology, seam and actual sole-floor review, then one exact pose with evaluated foot vertices. Contact keeps the existing fixed-floor criteria; no action-minimum floor or frame-dependent root correction is admissible. E full motion, other-view motion, recoil/projectile integration, eight directions, HTML and production remain HOLD. This document grants no execution permission.
