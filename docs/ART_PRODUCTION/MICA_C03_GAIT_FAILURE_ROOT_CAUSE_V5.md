# MICA C03 — V4 completion-report correction and V5 prevention gate

Status: **HOLD — visual completion not achieved**  
Reviewed: 2026-09-03 (Ponytail FULL independent audit + user-recording audit)

## What failed

The prior V4 completion claim was invalid.  The current motion provenance
shows that only the E direction used `walk_e_v4`; SE, S, SW, W, NW, N, and NE
used V3 fallback gait sources.  The resulting candidate was technically
packageable, but it was not an all-direction V4 low-lift correction.

Native V4 direction sheets and the user recording show that E has the revised
lower swing, while NE, SW, W, and NW retain visibly high swing/knee poses.
SE must also be re-reviewed.  A low-resolution user recording is diagnostic
only, but it is sufficient to invalidate a visual completion claim when it
matches the native direction-sheet defect.

## Root causes

1. `render_real_walk_cycle_blender_ual.py` accepted a silent per-direction
   fallback revision.  A partial repair therefore exported a mixed V4/V3
   candidate under one candidate name.
2. The structural gait contract only tested lower-body frame uniqueness and
   consecutive repeat count.  It could not reject high foot lift, wrong
   travel silhouette, poor planting, or unsuitable diagonal movement.
3. Motion promotion checked chroma, resolution, and provenance shape, but did
   not require a direction-by-direction visual acceptance record.
4. The previous 1920×1080 “eight-direction video” was generated by Python
   from atlas cells and sockets.  It did not execute the interactive HTML,
   exercise input-driven direction changes, or prove runtime frame selection.
5. The prior Ponytail PASS pinned an E gait review and one fire-frame muzzle
   review, not an auditable PASS for each gait direction.  Subsequent cleanup
   also left V4 review/contract records pointing at a deleted candidate and a
   missing Blender scene, making the stated evidence non-reproducible.
6. The attempted recovery through `render_fast_motion_blender_ual.py` also
   failed independent visual review.  Although it invoked Blender and UAL,
   its ``screen_left``/``screen_right`` hip, knee, and ankle UV coordinates
   were shared by every facing.  It applied a 0.15-unit foot lift intended
   for one generic source shape to eight incompatible non-neutral masters.
   E/W/NW/NE therefore developed high knees or bent silhouettes, while
   S/SE/N collapsed both feet or made the step unreadable.
7. Treating ImageGen's walking-pose sheets as the movement authority was the
   wrong separation of concerns.  Source art had pre-baked stride errors;
   Blender could only sequence or compound those errors instead of owning the
   actual leg motion.  This contradicted the approved rule: ImageGen authors
   original source art, while Blender+UAL implement movement.
8. The production MICA art profile did not point to the MICA runtime
   descriptor, and the shared fast runtime accepted only schema 1.  V5 uses
   schema 2 to store a muzzle position for every state and frame.  Therefore a
   correctly built V5 atlas could be skipped at activation or reduced to an
   obsolete direction-level muzzle coordinate in the actual game.

## Prevention rules now enforced

- The Blender renderer rejects `--fallback-gait-version` unless the caller
  explicitly supplies the diagnostic-only `--allow-mixed-source-revisions`
  override.  That override is never eligible for promotion.
- Atlas packaging derives the ImageGen gait revision from all 96 gait-source
  authority paths.  It rejects a mixed revision within a direction or across
  directions and records the single accepted revision in provenance.
- MICA requires V5 sources for **all eight directions**.  Promotion now
  requires a candidate-local `MICA_C03_FULL_8_DIRECTION_GAIT_ACCEPTANCE.json`
  from Ponytail FULL.  Every direction must be PASS and reference a native
  1920×1080-or-larger review image for the same candidate and source revision.
- A synthesized atlas video is auxiliary evidence only.  Final visual
  completion additionally requires a real interactive-HTML capture: eight
  movement directions, adjacent direction transitions, opposite direction
  transitions, and movement firing.  The capture must expose a build ID plus
  HTML/runtime hashes.
- Any changed gait atlas requires all 24 move-frame and all 6 fire-frame
  muzzle sockets to be regenerated and reviewed.  A source path, Blender
  scene, review artifact, or hash that cannot be resolved is a FAIL, never a
  retained PASS.
- V5 uses exactly one neutral, feet-planted 1024×1536 ImageGen master per
  direction.  The master must not itself contain a stride, high knee,
  toe-off, or hidden foot that a rig would amplify.
- Blender must receive `MICA_C03_DIRECTION_LEG_LANDMARKS_V5.json`, which
  supplies per-direction hip/knee/ankle/toe coordinates, front-leg order,
  stride, and a capped low swing.  The renderer refuses to run a promotable
  master-rig candidate without all eight landmark entries.
- Direction-master packaging records and compares the exact one-revision
  ImageGen master root.  It cannot silently substitute ``current`` or a
  previous facing set.
- Every promoted schema-2 operator must have a production-profile Godot smoke
  test.  The test loads the real registry profile and descriptor, enters all
  eight move sectors, compares the active frame's tracked muzzle to the
  projectile birth origin, then fires in a selected direction before the next
  process tick.  A synthetic schema-1 fixture remains a compatibility test,
  not evidence for a newly promoted character.
- Static contact sheets and portable HTML bundle checks are now labelled
  ``STATIC_*`` only.  They verify hashes, alpha, dimensions, and descriptor
  parity, but cannot grant a dynamic-runtime pass.  Browser or native runtime
  interaction must be captured and reviewed separately.
- The portable preview is repackaged from the promoted runtime only.  It
  contains all 24 RGBA atlases beside the HTML and verifies each copied hash
  against the runtime source, preventing an older preview copy from being
  mistaken for the current candidate.

## V5 completion sequence

1. Author and independently review one V5 neutral, feet-planted built-in
   ImageGen master for every direction; preserve MICA's approved costume and
   green source-background contract.
2. Normalize and hash all masters, lock their per-direction landmark file,
   then run the Blender+UAL two-bone rig with only its capped low foot arcs.
3. Package only if the one-revision master provenance check passes.
4. Produce one native direction review per direction and obtain Ponytail FULL
   PASS for support alternation, low swing height, planted contact, torso
   continuity, and direction-correct travel.
5. Promote, rebuild frame-indexed muzzle data, and create a real HTML runtime
   capture covering movement, transitions, and firing.
6. Run Ponytail FULL against that exact runtime hash.  Only then may the
   project report visual completion.
