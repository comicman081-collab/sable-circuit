# Motion Studio 작업 범위

## 신규 원화 투명 알파 필수 — 사용자 지시 2026-09-13

- 새로 생성/교체하는 원화는 실제 RGBA PNG이며 배경 알파 0, 가시 영역 1~255,
  내부는 불투명하다. 알파 255는 2026-09-28 사용자 지시로 기본 허용한다("254보다
  낫다"); 254로 깎지 않는다. 초록/크로마 배경과 그린 재시도는 금지다.
- `source_alpha_policy.py`가 반환 원본을 직접 검사한다. RGB 체커보드,
  빈 이미지, 투명한 여백 없이 흐릿해진 전면 이미지는 입장할 수 없다. 이 숫자
  검사는 시각 승인이 아니며 양쪽 매트에서 경계·내부·사격 자세를 직접 확인한다.
- 원본 알파를 강제로 낮추거나 키잉해서 원래부터 투명 생성된 것으로 취급하지 않는다.
  기존 승인 원화·녹색 원본과 검토 근거는 보존한다. 미승인 녹색 후보는 수정 대상이다.
  `intake_derived_frame.py`의 신규 입력은 차단되고 과거 파생본 검증만 유지한다.
  사용자가 명시적으로 허용한 경우에 한해 `web_alpha_bridge.py`가 실패한
  그린/근-그린 결과를 `WEB_ALPHA_BRIDGE_ONLY` 격리 입력으로 기록할 수 있다.
  기존 GPT 웹 대화에서 반환된 파일도 실제 RGBA 네이티브 알파 검사를 통과하기
  전에는 가져오지 않는다. 브리지 원본의 로컬 키잉·크롭·재작성·직접 승인은 금지다.
- ImageGen에 넘기는 외형 원본과 UAL 포즈 가이드는 SABLE 저장소 안의 파일만
  허용하고, 외형 원본은 레시피의 identity reference와 일치해야 한다.
  `source_alpha_policy.require_project_reference`가 다른 프로젝트·다른 SABLE
  캐릭터·Codex 관리 스테이징·클립보드와 잠긴 구형 도구 경로를 거부한다. 관리
  스테이징은 새로 반환된 결과를 프로젝트로 복사해 실제 응답에 묶을 때만 출력
  경로로 허용한다.

  만들지 않으며 `site7_shield`의 인간형 원화/걷기 생성은 재개하지 않는다.
- `../data/art_profiles/site7_enemy_body_plan.json`이 범위 기준이다. 로봇의
  방향·총구·차체 이동·예고/공격을 검토하며 사람의 6위상 걸음 검사를 강요하지

- 실제 이미지와 동작을 보고 판단한다. 기술 검사 결과를 시각 품질 판정으로 바꾸지 않는다.
- 보행 수정은 현재 스킬의 `references/gait-repair.md`를 따른다. 좌표 이동과 사격 검사만으로 걷기 완료를 보고하지 않는다. 실제 선택된 렌더러의 비사격 walk/run 프레임 진행, 이동 사격 시 동일 보행 유지, 정지 사격 시 고정된 접지발을 검사한다. 새 레시피는 `authored_frames` 공통 경로를 쓰며 구형 ASTER 다리 변형 번들을 끼워 넣지 않는다.
- MICA의 현 상태와 남은 편차는 README에 적혀 있다. 별도 달리기·옆걸음·손 재장전 클립이나 64개 신체 조합이 완성됐다고 쓰지 않는다.
- 사용자가 요청하기 전에는 Luna 재현 테스트나 하위 에이전트 작업을 시작하지 않는다.
- 기존 게임 포인터를 바꾸는 일은 이 독립 HTML 제작에 포함되지 않는다.

## 현재 공통 구현과 재사용 절차 — 2026-09-10

- 이동 사격에서는 `combat-aim.js`가 실제 총구·조준점·몸 방향을 함께 해결하고 몸과 탄환에 같은 조준각을 적용한다. 발사 함수에서 다른 각도를 다시 계산하지 않는다. 총구보다 안쪽의 조준점 때문에 탄환만 뒤로 꺾지 않는다. 연사 중에도 새 이동 키와 실제 마우스 움직임 중 마지막 방향 입력이 우선한다.
- 다음 캐릭터와 현대식 레시피의 원화 수정에는 `character_workflow.py status/build/review-source/verify-runtime/review-runtime/deliver`를 사용한다. 실제 검토 없이 승인 기록을 만들거나 오래된 해시만 바꿔 통과시키지 않는다.
- 빌드 실패와 부분 빌드는 기존 캐릭터 아틀라스를 교체하지 않는다. 캐릭터별 HTML과 보고서를 분리하며 `--activate-preview`는 사용자가 보고 있는 공통 미리보기 변경을 요청한 경우에만 쓴다.
- 사용자는 다음 캐릭터에서 Luna도 사용할 수 있는 시스템 구축을 요청했다. 이 요청을 새 캐릭터 생성이나 하위 에이전트 실행을 이미 마쳤다는 뜻으로 해석하지 않는다. 실제 검증 범위는 `qa/WORKFLOW_READINESS_2026-09-10.md`를 따른다.
- 사용자가 Luna Max를 명시한 경우에만 이름이 지정된 슬롯에 `gpt-5.6-luna` 단일
  시도를 허용한다. 외형·포즈 참조는 `source_alpha_policy`의 프로젝트 경로
  가드를 먼저 통과해야 하며, 다른 프로젝트 이미지·RGB/체커보드·알파 실패는
  변환 없이 격리 HOLD로 남긴다. 실패 뒤 반복 생성이나 성공 주장을 하지 않는다.
  단, 사용자가 명시적으로 그린 배경 후 GPT 웹 투명 변환을 요청한 경우에는
  실패 결과 하나를 `web_alpha_bridge.py`로 격리 기록해 해당 대화에 보내는
  단일 브리지를 허용한다. 웹 반환물은 동일한 알파 게이트와 실제 응답 해시가
  확인될 때만 다음 단계로 간다.
- ASTER 2026-09-11 재개 지점은 `qa/aster/GAIT_REPAIR_2026-09-11.md`다. 고정 프레임/구형 다리 변형 연결은 수정됐지만 E/walk/1·4와 NW/walk/2 원화 연속성은 시각 HOLD다. 57개 브라우저 기술 검사 통과를 완성 보행 승인으로 바꾸지 않는다. 원화 또는 런타임 거절 시 이전 전달 기록은 보존하고 현재 delivery 상태를 HOLD로 무효화한다.

- 실제 거절된 원화 슬롯을 누락 슬롯 양산보다 먼저 처리한다. 스캐폴드의 무기/속도 수치를 그 캐릭터의 게임 규칙으로 오인하지 않는다. 재개 패킷과 회귀 시험은 Luna 실생성 성공이 아니며, 모델 변경·하위 에이전트 실행을 자동 허가하지 않는다.

## 보행 실패 차단 — 2026-09-13

- `gait_contract.py`가 위상 번호의 단일 기준이다. 0/3 접지, 1/4 뒤쪽 스윙, 2/5 전방 통과를 다른 의미로 바꾸지 않는다.
- 새 전신 보행은 현재 스킬의 `references/cycle-review.md`를 따른다. `prepare-cycle`의 실제 영상·원화와 관측 좌표/시간을 검토한 `review-cycle`이 필요하다. E 한 주기 승인 전에는 다른 방향 생성·가져오기·승인을 확대하지 않는다.
- 모든 소스 파일이 있어도 주기 검토가 없으면 정식 빌드가 거절된다. 직접 compiler를 호출하거나 부분 후보를 옮겨 우회하지 않는다. `--partial`은 격리된 진단만 허용한다.
- ROOK의 이전 사용자 거절 빌드는 계속 거절 상태로 보존한다. 2026-09-13 Astra가 원화와 주기를 다시 검토한 새 빌드 `334814808cdfadc0…`는 별도의 실제 영상·관찰·57개 브라우저 검사로 MVP 전달을 승인했다. 근거와 한계는 `qa/rook/astra_repair_20260913/RESULT_KO.md` 및 현재 `dist/rook.delivery.json`을 확인한다. 이 승인을 이전 빌드, 별도 질주 원화 또는 Luna 실생성 성공으로 확대하지 않는다. 새 거절은 여전히 handoff의 최우선 수정 작업이다.
- 최종 런타임 승인은 `prepare-runtime-review`로 만든 실제 영상/빌드에 묶인 시간대별 관찰을 `--observations`로 요구한다. 좌우 발 표식과 관측 좌표를 프롬프트나 기대값에서 만들어 넣지 않는다.
