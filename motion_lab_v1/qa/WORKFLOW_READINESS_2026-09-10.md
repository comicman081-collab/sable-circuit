# Motion Studio 공통 구현과 다음 캐릭터 절차

## 현재 구현

사용자가 확인한 MICA 시제품을 기준으로 이동 사격 오류를 수정했다. 실제 총구·조준점·8방향 몸 프레임을 함께 해결하고 몸과 탄환에 하나의 조준 결과를 적용한다. 발사 단계에서 탄환의 각도만 다시 계산하지 않는다. 무기보다 안쪽을 조준하면 탄환이 몸 뒤로 꺾이지 않도록 전방 조준을 유지한다. 사격을 유지해도 새 WASD 입력이 방향을 전환하며 다음 마우스 움직임이 다시 독립 조준을 가져온다. 키 반복은 조준을 빼앗지 않는다.

수정 전 사용자 사격 기록 273개 중 75개가 몸의 8방향 각도와 45도 넘게 달랐고 최대 차이는 약 150.51도였다. 원자료는 `moving_fire_before_20260910.json`이다. 수정 후 8방향 마우스 조준, 8방향 키보드 전환과 키 반복 검사를 실제 마우스 버튼을 누른 상태에서 실행했다. 이벤트 및 프레임 검증 방법을 보고서에 구분해 적었다.

## 새 작업자가 재사용할 것

- 저장소 루트에서 자동 검색되는 `.agents/skills/sable-character-studio/SKILL.md`와 루트/실험실 `AGENTS.md`가 새 경로를 지정한다. 과거 스킬은 명시적인 역사 자료 감사용으로 범위를 좁혔다.
- `character_workflow.py status`는 정해진 캐릭터의 누락·중복·변경·미검토 슬롯과 다음 파일을 표시한다. E 대기 및 양쪽 접지 보행을 먼저 확인하고, 성공한 원화만 확장한다.
- 실제 ImageGen 출력 메타데이터, 소스·참조·시각 검토 증거를 해시로 연결한다. 원화나 참조가 바뀌면 이전 승인으로 빌드할 수 없다. 검사기가 그림의 의미나 미관을 자동 판정한다고 주장하지 않는다.
- 새 캐릭터는 레시피와 원화만 추가한다. MICA의 얼굴이나 런타임을 복제·개조하지 않는다. 단독 프레임에서도 자신의 전면 아틀라스로 초상화를 생성한다.
- 후보 폴더에서 완성한 빌드만 해당 캐릭터의 개발 아틀라스로 교체한다. 실패/부분 빌드와 이전 버전은 보존하며, 공통 사용자 미리보기는 명시적으로 활성화할 때만 바뀐다.
- 캐릭터별 HTML·패키지·검사 결과를 분리했다. 캐릭터·아틀라스·런타임·검사 코드가 다르면 브라우저 통과 기록을 재사용할 수 없다. 새 캐릭터 최종 전달에는 현재 원화 검토, 실제 실행 검사, 1080p 시각 검토가 각각 필요하다.

## 검증과 한계

최종 수정본의 실행 기록은 `mica/latest_runtime_check.json`이며 상태는 `PASS_RUNTIME_CHECKS`다. JavaScript 21개, Python 16개, 실제 마우스 버튼 유지 상태의 브라우저 17개 검사가 통과했다. 최종 방향 전환 원자료는 `mica_combat_browser_final_20260910.json`이며 각 전환 이후 실제 발사 29개를 중복 없이 관찰했다. 초기 검사기의 프레임별 중복 집계를 제거한 뒤 다시 실행한 결과다. 네이티브 캡처는 `mica_runtime_20260910_1080p.png`이고 해상도·디코딩 검사는 `mica/visual_evidence_1080p.json`에 기록했다. 브라우저 오류/경고와 외부 리소스 요청은 관찰되지 않았다.

현재 패키지 입력 SHA-256은 `c3f6ac47e2f720025f2552ffd4ca0173184a4fdc1c00cc11c2a2c9b0665ff99e`, HTML SHA-256은 `e7b85b31384e2231bc796265f3bc61bdf8b2bf1a92b01d6ddbf2640f245692b7`이다. `dist/mica.package.json`을 기준으로 하며, 수정 전이나 중간 패키지의 검사 기록을 현재 PASS로 재사용하지 않는다.

JavaScript 회귀 검사는 이동/조준 8×8, 30/60/120Hz, 대각선·IME 형태의 값, 이동 사격 중 조준 전환, 짧은 클릭, 연사·재장전과 충돌을 검사한다. Python 검사는 누락·중복·오래된 승인·잘못된 캐릭터·가짜 PASS 표기·실패한 빌드·단독 프레임 초상화 경로 등의 기술적 고장을 주입해 차단 여부를 확인한다. 시험용 입력은 `qa/technical_tests/`에만 두며 원화나 생산 성공 사례로 사용하지 않는다.

현재 결과는 수정된 MICA 런타임과 재사용 도구의 기술/브라우저 검증이다. **새 캐릭터를 실제로 생성한 Luna 재현 실행은 아직 하지 않았다.** 무결한 첫 출력이나 예술적 품질을 모델 이름만으로 보장하지 않는다. 다음 실제 캐릭터에서는 동일한 절차로 잘못된 슬롯을 검출하고 해당 부분을 수정한다.

기존 MICA의 48개 보행·8개 대기 원화와 알려진 외형 편차는 그대로다. 전용 달리기, 옆걸음, 손 재장전 원화를 추가했다고 주장하지 않는다. 기존 MICA의 쌍 원화 자료는 새 개별 검토 이력이 아니므로 소급 승인을 만들어 넣지 않는다.

## 구성 방식의 근거

저장소 루트 `.agents/skills` 배치와 설명 기반 선택은 [공식 스킬 문서](https://learn.chatgpt.com/docs/build-skills)를, 프로젝트/하위 폴더 지침 연결은 [공식 AGENTS.md 문서](https://learn.chatgpt.com/docs/agent-configuration/agents-md)를 확인했다. 이는 설정/발견 방식의 근거이지 캐릭터 품질 검증 결과가 아니다.
