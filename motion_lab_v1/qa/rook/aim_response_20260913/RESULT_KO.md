# ROOK 빠른 조준 반응 개선 — 2026-09-13

현재 사용자가 수용한 보행·원화는 유지하고 조준 입력 대기를 제거했다.

## 원인과 수정

- 기존 `pointermove`는 좌표만 저장하고 다음 120Hz 물리 업데이트에서 조준을 계산했다. 실제 좌우 반전 8회에서 입력 직후에는 이전 방향이 남았고 다음 화면 약 8.3–10.7ms 뒤에 반영됐다. 근거: `qa/rook_aim_baseline.json`.
- `applyPointerAim`을 입력 처리 안에서 호출한다. 이동/반동/카메라 갱신 후 발사 직전, 물리 업데이트가 없는 화면의 렌더 직전에도 같은 총구 기준 해법으로 갱신한다.
- 변경된 패키지 입력은 `public/combat-aim.js`, `public/studio.js` 두 개뿐이다. 이전 수용 빌드의 영상 메타데이터 `qa/rook_motion_astra_20260913.json` 내 입력 해시와 대조했다. 원화·아틀라스·레시피·simulation·renderer는 동일하다.
- 발사 간격 0.42초, 탄창 10발, 재장전 1.38초와 비행 탄환의 직진 궤적은 유지했다. 발사 사이의 대기시간까지 없앤 연사력 변경은 아니다.

## 실제 검증

- 기존 이동 사격 17/17, 급회전 16/16, 보행 40/40.
- 최종 급회전 검사: 세 입력을 연속 처리한 조준 계산 최대 1.30ms, 첫 화면 관측 최대 10.70ms. 즉시/첫 화면/첫 발사 가능 시점의 조준 오차 모두 허용 범위 안. 전체 표시 지연이 1.3ms라는 뜻은 아니다.
- 보고서: `qa/rook_aim_combat_browser_final.json`, `qa/rook_aim_locomotion_browser.json`.
- 새 네이티브 영상 `qa/rook_aim_motion_20260913.webm`: 1920×1080, 38.024초, 실제 디코딩 1,139프레임. 24구간 144개 순차 샘플과 영상 재생을 확인했다. 관찰은 이 폴더 `runtime_observations.json`에 별도 기록했다.
- Node는 30개 검사로 30/60/120Hz 반전, 발사 간격/발걸음 불변, 기존 탄환 비유도성을 검사한다. Python은 기존 보고서 우회와 인계 문서 변경을 거절한다. 최종 실행 결과는 `dist/rook.delivery.json`의 현재 로그를 따른다.
- 1080p 컨테이너/디코딩 검사 PASS는 미술 품질 자동 승인이 아니다. 기존 6프레임의 짧은 접지 미끄러짐과 빠른 보행 재사용 한계는 그대로다.

## Luna 재사용

스킬에 `references/aim-response.md`를 추가하고 브라우저 절차, README, AGENTS를 갱신했다. 하네스는 기존 17개 결과만으로 전달하지 못하며 급회전의 입력 직후·첫 화면·첫 발사 가능 시점을 모두 요구한다. 이동한 척하는 정지 사례, 지연, 비행 탄환 방향 변경, NaN 시간도 거절한다. 새 조준 문서의 해시도 인계 패킷에 포함한다.

이 작업은 Astra의 실제 수정·검증이다. Luna 재실행이나 무조건적인 향후 성공을 주장하지 않는다. 현재 패키지는 `dist/ROOK_Motion_Studio.html`, 브라우저는 `http://127.0.0.1:14824/standalone/rook.html`이다. 다른 캐릭터, 공통 미리보기, 게임 포인터와 배포는 변경하지 않았다.
