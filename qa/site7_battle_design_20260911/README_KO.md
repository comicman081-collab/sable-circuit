# SITE-7 인앱 전투 디자인 — 2026-09-11

## 현재 적용

- 기준: `art_src/environments/site7/references/IMAGE_A_ENVIRONMENT_QUALITY_REFERENCE.png`.
- 실제 Godot `StoryStage01`에 기존 스테이지 1~3 배경 45장(각 8개 방 + 7개 연결 구간)을 연결했다. 다른 시스템 작업트리의 승인된 배경 목록과 스테이지 2/3 데이터를 읽어 이 앱에 통합했다. 다른 작업트리는 수정하지 않았다.
- 구형 SVG 바닥/소품/과도한 장식 레이어는 숨겼다. 기존 PNG의 조명과 색을 보존하고, 한 번에 한 장만 불투명하게 표시한다. 방 좌표는 현재 미션 데이터에 맞춰 연결한다.
- 얇은 HUD, 현재 ASTER·MICA 원화에서 가져온 초상, 실제 탄약·체력·스킬·에너지·적 수 표시를 적용했다.
- ASTER·MICA는 현재 Motion Studio의 동일한 전신 프레임/총구/보행 런타임을 사용한다. ROOK는 기존 임시 아틀라스(화면 분리용 크로마 셰이더), 적은 기존 목업이다. 신규 캐릭터나 적 원화 완성으로 주장하지 않는다.
- 사용자 최종 요청에 따라 **처음 화면의 1.8배**로 세 캐릭터를 설정했다. ASTER·MICA는 기준 높이 72 → 129.6 월드 픽셀, ROOK는 표시 배율 0.245 → 0.441이다. 이전 확대 상태에 다시 배율을 곱하지 않았다. 카메라 줌/HUD 크기와 캐릭터 이동 속도·보행 주기는 그대로다. 카메라의 수평 중심과 동료 간격은 왼쪽 HUD 여백을 고려해 조정했다.
- 접지 앵커와 총구 변환은 같은 표시 배율을 사용한다. 그림자는 불투명 배경보다 위에, 발 위치에 표시한다. 적의 중복 체력바/원형 가짜 그림자는 제거했다.
- 스테이지별 일반전·엘리트전·보스전, 총 9개 교전의 바닥 경계를 기존 이미지 좌표에 연결했다. 해당 교전 동안 배경을 고정하고 발 위치가 경계를 넘어가지 않도록 제한한다. 동료 목표점도 같은 경계로 제한하며, 보행 위상은 제한 후 실제 변위만 소비한다.
- 탄환은 발밑 원 대신 캐릭터·목업 적의 몸통 사각 범위에 대해 구간 충돌 검사한다. 한 프레임에 지나간 몸통도 맞고, 같은 구간의 적 중 가장 먼저 만난 적만 맞는다. 몸통 사각 범위는 실루엣 픽셀 단위 충돌 마스크가 아니다.
- Motion Studio의 `combat-aim.js`와 같은 방식으로 현재 전신 프레임의 총구와 8방향을 함께 선택해 조준점까지 탄환 방향을 계산한다. 총구보다 가까운 점은 기존 근접 방향 fallback을 사용하며 정확한 수렴으로 주장하지 않는다.
- 접지 Y 순서로 몸체를 정렬하고 그림자·발사체·충격·체력바의 표시 순서를 분리했다. 실제 적 위에 조준하면 조준점 색이 바뀌고, 명중/재장전/피해 표시를 실제 런타임 이벤트에 연결했다.
- 살아 있는 변이체 목업이 피격 때마다 몸통 회전을 누적해 거꾸로 뒤집히던 기존 오류를 수정했다. 반응은 제한된 각도에서 회복하며 프레임 수만큼 누적되지 않는다.

## 실행

프로젝트를 Godot로 실행하고 제목 화면의 `01 / BLACKOUT`, `02 / RECOVERY`, `03 / INNER BREACH`를 선택한다. 모두 기존 인앱 전투 씬과 실제 입력·동료 AI·적 AI·피해 처리를 사용한다. 기존 `ENTER OPERATIONS` 캠페인 경로도 유지된다.

직접 교전 진입은 저장 보상을 지급하지 않는다. `WASD` 이동, `Shift` 달리기, 좌클릭 사격, `R` 재장전, `1/2/3` 캐릭터 전환, `Q/E/X` 스킬, `F6` 교전 재시작, `F7` 일반전→엘리트전→보스전 전환, `Esc` 제목 화면. 전멸시킨 교전에서는 `F`로 다음 교전으로 이동한다. 재시작은 체력/탄약뿐 아니라 재장전과 사격 대기도 초기화한다.

명령줄 직접 진입: Godot에 `--path <프로젝트 경로> -- --battle-stage=1` (1~3)을 전달한다. 웹 배포는 수행하지 않았다.
