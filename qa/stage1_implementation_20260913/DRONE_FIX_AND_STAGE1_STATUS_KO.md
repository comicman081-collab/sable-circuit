# 드론 반대 방향 오류 수정 / 현재 범위

> 아래는 round8 제출 시점의 기록이다. 이후 round8 실제 답변의 촬영 결함
> 수정, 실제 Godot 52개·Python 101개 검사, 새 보스 촬영과 round9 제출은
> `RESUME_AFTER_ROUND9_SUBMISSION.md`를 참조한다. Round8은 더 이상 답변
> 대기가 아니다. SE 전체 주기는 후반 총/상체 투영 차이로 수정 필요로
> 기록했고 후반 원화 교체 중이다. 과거 14/56 소스 검토를 주기 PASS로
> 해석하지 않는다.

2026-09-13. 드론의 한 장짜리 정면 그림을 반대쪽 사격에도 사용했던 것이
스크린샷의 직접 원인이다. 단순히 탄환 각도를 바꾸는 것으로는 해결되지 않았다.

## 반영

- 별도로 제작·관찰한 8방향 그림을 앱의 드론 프로필에 연결했다. 각 방향은
  자기 그림의 실제 자홍색 발사구를 쓴다. 원화의 비대칭 센서를 좌우 반전하지 않는다.
- 기존 목업 소총/권총/팔은 이미 조준 방향으로 회전하는 뼈에 붙어 있는데
  추가 좌우 반전까지 적용되어 있었다. 무기 쪽의 중복 반전을 제거했다.
- 적은 공격 준비 동안 예고 방향을 고정하고, 회복 상태에서 새 표적을 따른다.
  발사구 안쪽의 표적에 역방향으로 쏘지 않고 재배치한다.
- 같은 그림의 메타데이터/투명 영역 RGB만 바꾼 중복 8방향 등록을 거부한다.
  경직으로 공격이 취소되면 예고선을 그린 노드 자체를 다시 그린다.
- 플레이어 3명의 원화·보행·크기·사격 수치는 변경하지 않았다.
- 고정형 보스는 검토한 중앙 코어 원화를 기본 앱 레지스트리에 연결했다.
  네 팔을 개별 조준시키는 구현이 아니라, 고정 몸체의 중앙 보라색 발사구를 쓴다.
  체력바는 피격 영역 대신 전체 원화의 변환된 외곽 위에 배치해 기둥과의 겹침을 고쳤다.

## 실제 검증

- 앱 기본 등록 경로: 170개 검사 통과. QA 텍스처를 직접 주입하지 않았다.
  보스 연결 후 다시 실행한 `drone_app_1789289734_917.json`이 현재 레지스트리 근거다.
- 실제 발사 주체/회수 검사: 339개 통과. `emissions/1789286318_241/`.
- 경계 조건과 경직 전후 실제 렌더 픽셀: 46개 통과.
  `machine_edges_1789286316_995/report.json`.
- 후보 방향 검사는 240개 통과했다. 소스 검사는 전체 원화/체력바 변환
  회귀 48개를 추가한 현재 본문에서 436개 통과했다.
- 보스 기본 앱 경로는 `anchor_app_1789289257_709.json`, 271개 통과.
  8방향 표적 × 30/60/120Hz에서 실제 중앙 발사구·예고 고정·탄환 생성을 검사했다.
  종료 시 84개 ObjectDB 경고가 남아 있다. 이 실행의 객체별 분류는 미확인이다.
- 보스 앱 연결 후 3단계의 예고/발사/지면 공격을 통제된 조건으로 촬영했다.
  `anchor_native_1789289325_473/` 22장, `anchor_app_1080p.json` 해상도 검사 통과.
  실제 관찰: phase1_attack1_attack과 phase3_attack2_ground_warning에서 중앙 코어
  발사, 읽을 수 있는 지면 예고, 원화와 겹치지 않는 체력바를 확인했다.
  HP/공격 순번은 촬영용 조건이므로 이 캡처를 무수정 전체 플레이로 부르지 않는다.
- Python 워크플로 전체 회귀 96개를 다시 실행해 통과했다(215.733초).
  합성/잘못된 영상 입력을 포함한 기술 검사이며 실제 원화 승인 검사는 아니다.
- 기본 앱 등록 경로의 1920x1080 캡처 24장:
  `facing_native_1789286447_63/`; `facing_app_1080p.json`은 해상도/디코딩 검사다.
  8방향 원화는 앞선 동일 픽셀 캡처에서 모두 관찰했고, 앱 연결 후 W/NE도
  재관찰했다. 통제된 방향 사례이며 실제 플레이 전체 영상이라는 주장은 아니다.
- `full_operation.json`: 실제 전투 로직으로 6개 구역, 선택 구역 2개,
  적 10체와 보스, 상호작용 및 탈출 성공. HP/탄약 무한화나 적 삭제 없이
  테스트 봇이 물리·무기·충돌·상호작용을 구동했다. 인간 난이도 평가와는 다르다.
  이번 경로에서는 ASTER가 쓰러지고 ROOK/MICA가 생존했다.
- 짧은 headless 발사 시험 종료 시 AudioStreamWAV/PlaybackWAV 객체 경고가
  남는다. 상세 실행으로 오디오 객체임을 확인했다. 테스트 종료 시 정지와
  짧은 대기만으로 사라지지 않았으므로 해결됐다고 기록하지 않는다.
  현재 전체 경로와 네이티브 캡처 stderr에는 오류가 없었다.
- 전체 분대를 숨기지 않은 일반 전투 기본 앱 경로도 촬영했다:
  `machine_native_preview_1789287097_122/`. sample 004는 드론이 분대를 향해
  발사하는 장면, 014는 피격 후 추락, 025는 적이 사라진 구역 클리어다.
  세 장을 실제 관찰했고 30개 캡처는 `battle_app_1080p.json`으로 확인했다.

`motion_lab_v1/qa/stage1_enemies_20260913/cycle_capture/gpt6pro_review_round7.json`에

Godot 재실행·앱 로더 전체·원화·MVP·Luna 성공 승인은 아니다.

같은 대화에 round 8 변경 코드와 세 다리 수정 전후 이미지를 실제 제출했다.
현재 답변 대기이며 `gpt6pro_round8_submission.json`에 전송 관찰을 기록했다.
새 두 다리 연결 검사 지침과 보스 앱/체력바/촬영 검사의 좁은 범위 검토다.

소총병은 승인된 E 전신 보행 한 주기를 보존하고 SE 0~5 및 정지 원화까지
분리/외형을 검토했다(전체 소스 14/56). 체크무늬 배경, 지지 다리 반전, 사용자 지적의 세 번째
무릎/정강이 실패 원화는 모두 격리 보존했다. SE3은 정확히 두 다리로 이어지는
새 원화로 교체해 소스 검토했지만 SE 전체 주기와 앱 연결은 아직 승인되지 않았다.
나머지 방향·방패병·변이체의 실제 접지 보행은 미완료다.
이 보고서는 전체 몹 제작 또는 전체 MVP 완료 선언이 아니다.
