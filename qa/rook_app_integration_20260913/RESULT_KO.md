# ROOK 앱 연결 — 2026-09-13

사용자가 수용한 현재 ROOK을 실제 Godot 앱에 연결했다. 원화, 아틀라스,
레시피와 단독 HTML은 재생성/수정하지 않았다. 온라인 배포는 하지 않았다.

## 반영

- 앱 레지스트리의 예전 ROOK FastRuntime 포인터를 제거하고, ASTER/MICA와
  같은 MotionLabCharacterRuntime 경로에 ROOK의 8방향 walk/idle을 연결.
- 세 캐릭터의 기준 높이 129.6px, 즉 이전 사용자 지시 1.8배 유지.
- 현재 `portrait.png`의 얼굴/상체 영역 `[154,28,198,224]`를 전투 카드와
  기지 로비에서 함께 사용. 원본 픽셀은 그대로이며 예전 크로마 셰이더 제거.
- ROOK / TEMP 및 ROOK MOCKUP 문구 제거. 적 목업 표시는 유지.
- 앱 브리지에서 Studio의 후진 위상 선택을 사용하고, 총구 계산에도 같은
  방향별 위상을 사용. 포인터 이벤트/표시/발사 전 최신 조준을 함께 반영.
- 게임 밸런스는 별도 유지: 걷기 138, 달리기 205 game px/s; 10발,
  발사 간격 .42초, 재장전 1.38초, 1회 1발 소비/5개 산탄, 탄속 760,
  기본 산탄 피해 7. 이미 발사된 산탄의 방향은 변경하지 않음.

## 실제 검증과 관측

- 새 `rook_motion_lab_app_smoke.gd`: 1,895 assertions 통과. 실제 Actor의
  CharacterBody2D 이동과 물리 메서드로 30/60/120Hz, 8방향 walk/run,
  8×8 이동/조준 사격, 총구/탄환 일치, 탄창/쿨다운/재장전, 기존 탄환 방향,
  전투/로비 초상화 원본 픽셀 일치를 확인. 합성 엔진 입력/테스트 상태이며
  물리 키보드나 사람의 자연스러운 보행 판정을 대체하지 않는다.
- 기존 MotionLab 3인 연결, prototype, M7, M3, Site7 흐름/기하 검사를 실행.
  Site7 기하 1,012 assertions 통과. 프로젝트 정적 검사도 통과.
- 실제 NVIDIA OpenGL Godot 렌더러에서 세 스테이지의 2번 키 ROOK 선택,
  D+S 대각선, 좌클릭 유지 사격, 급회전 및 R 재장전을 실행해 캡처.
  모든 스테이지에서 새 흰 단발/흑금색 복장, 올려 든 산탄총, 다른 캐릭터와
  같은 크기 및 깨끗한 초상화를 확인했다. run 연속 캡처에서 다리 포즈가
  실제 이동에 따라 교대한다. 이 정지 캡처를 새로운 전체 보행 영상 승인으로
  주장하지 않으며 기존 수용된 원화 주기 승인은 그대로 유지한다.
- 최초 로비 캡처에 앞 전투의 짧은 수명 VFX가 남아 있음을 관측했다.
  최초 증거는 보존하고, 최종 캡처에서는 효과의 정상 수명이 끝난 뒤 로비를
  촬영한다. 화면을 편집해 제거하지 않는다.

## 범위와 잔존 한계

현재 승인된 6프레임 보행을 그대로 사용한다. 별도 질주/64개 전용 스트레이프/
손 재장전 원화를 새로 만든 작업이 아니다. 앱의 기존 전신 스프라이트 브리지이며
Studio의 세부 상체 메쉬 반동까지 이식했다고 주장하지 않는다.
모델 변경이나 Luna 실재현은 하지 않았다. 예전 실패 원화/기록은 삭제하지 않았다.
일부 기존 Godot smoke의 종료 시 ObjectDB 잔류 경고는 별도 남아 있으며,
스크립트 오류를 통과로 취급하지 않는다. 처음 발생한 미등록 클래스 참조 오류는
명시적인 preload로 수정하고 새 로그에서 재검증했다.

현재 원화/HTML과 승인된 패키지 입력의 해시 일치, 실제 테스트 로그와
1080p 파일의 해시는 같은 폴더의 `integration_manifest.json`에 기록한다.
