# 타격 이펙트 그리기 성능 수정 — 2026-09-25 (WP-2 중 발견)

## 발견
- 웹 빌드 FPS 측정(WP-2)에서 작전 1 전투 후반 FPS가 옛 빌드보다 낮게 나왔다: 20~24 대 33~35.
  - 이 두 값은 서로 다른 시각에 잰 것이다.
  - 나중에 같은 세션에서 빌드를 번갈아 잰 웹 비교에서는 차이가 없었다. `qa/web_fps_20260925/RESULT_KO.md` 참고.
  - 따라서 웹 FPS 차이를 이펙트 탓으로 본 것은 입증되지 않았다.
- 로컬(네이티브) 성능 저하는 실제였다. 커밋을 거슬러 확인하니 원인은 `dfad7621b`(타격·피격 이펙트 이식)이다.
  - 조건: 작전 1 전투 미리보기를 30초 동안 연속 교전하고, 적이 없으면 다시 스폰한다. 창 모드, RTX 4070 SUPER, OpenGL 3.3 Compatibility.
  - 결과: 이펙트 이식 전 107~124fps, 이식 후 48~75fps. 당시 한 번씩 잰 값이다.
- 원인을 좁혔다.
  - 조명(`PointLight2D`)을 꺼도 그대로였다.
  - `_draw`를 끄면 113~127fps로 돌아왔다.
- 원인은 이펙트마다 매 프레임 도형을 하나씩 그리는 호출이었다.
  - `draw_circle` / `draw_colored_polygon`은 호출마다 따로 다각형을 만들고 GPU 버퍼를 올린다.
  - 부드러운 번짐 하나가 원 5개였다.
  - 산탄 한 번에 이펙트가 여러 개 생겨, 교전 중 평균 8개, 최대 22개가 떠 있었다. 이때 프레임당 수백 번 호출됐다.

## 수정 (`scripts/vfx/combat_hit_vfx.gd`)
- 부드러운 번짐(원 5개)을 방사형 그라디언트 텍스처 사각형 1개로 바꿨다.
  - 그라디언트는 옛 원 5개를 더한 계단 모양의 각 경계 중간값을 이은 것이다. 가운데 알파 0.77, 반경 1.35배까지다.
  - 전체 빛의 양은 옛것의 0.992배다.
- 줄무늬, 파편, 작은 원, 리본, 접촉 섬광의 원은 삼각형으로 모았다. 한 이펙트가 프레임마다 `RenderingServer.canvas_item_add_triangle_array` 한 번으로 보낸다.
  - 노드가 가산 혼합이라 그리는 순서가 바뀌어도 결과는 같다.
  - 접촉 섬광의 타원 변형은 삼각형 좌표에 직접 적용한다.
- `_draw` 안의 중복 `_sync_visual_layers` 호출을 뺐다. `_process`에서 이미 부른다.
- 두 번째 커밋: 볼륨층과 조명의 고정값(색, 크기, 방향, 에너지, 스타일)을 setup에서 한 번만 정한다.
  - 매 프레임에는 진행도와 조명 감쇠만 바꾼다. 전에는 매 프레임 색 문자열을 다시 해석하고 셰이더 값 6개를 다시 넣었다.
  - 아래 비교에서 FPS 차이는 측정되지 않았다. 하는 일이 줄어든 정리다.
- 모양, 색, 수명, 방향, 무작위 배치, 셰이더 볼륨층, 조명, `debug_vfx_contract()`는 그대로다.
